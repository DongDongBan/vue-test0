# 任务看板 · Vue 3 教学文档

这份文档写给**刚学 Vue 3、想通过一个完整项目理解「工程化写法」的人**。它不是 API 手册，而是解释「为什么这样分层、这样写」，以及每一步用到了什么知识点。

配合阅读：

- [需求规格说明书](./需求规格说明书.md)：先看需求，再看实现
- [验收清单](./验收清单.md)：自己跑一遍，对照预期

```bash
npm install
npm run dev
```

浏览器打开终端提示的地址。建议同时做三件事：

## 2. 三个心智模型

### 2.1 组件树

```
App.vue
├── BoardToolbar.vue          搜索与筛选
├── BoardColumn.vue × 3       三列
│   └── TaskCard.vue          每张卡片
├── TaskFormDialog.vue        新建/编辑（条件渲染）
├── ConfirmDialog.vue         删除确认（条件渲染）
└── ToastHost.vue             提示（常驻）
```

**状态只在 `App.vue` 创建一次**，通过 props 往下传，通过事件往上抛。

### 2.2 单向数据流

```
用户操作 → 命令（addTask/moveTask…）→ 新状态 → computed 派生 → 视图更新
```

没有双向绑定到全局状态，没有子组件直接改父组件数据。这是本项目最重要的约束。

### 2.3 分层

```
components/     只负责“长什么样、点了发什么事件”
     ↓
composables/    负责“响应式状态 + 什么时候写盘”
     ↓
domain/         负责“规则”，纯 JS，不 import vue
```

依赖只能向下。`domain` 不认识 Vue，所以它可以被任何地方复用，也最容易推理。

## 3. 领域层：把规则从界面里拿出来

### 3.1 `task.js`：常量、校验、日期

关键点：

```js
export const STATUSES = [
  { value: 'todo', label: '待办' },
  { value: 'doing', label: '进行中' },
  { value: 'done', label: '已完成' },
]
```

- **单一事实来源**：列的顺序、显示名、合法性判断都来自这一个数组。`STATUS_VALUES` 和 `STATUS_LABELS` 由它派生，不手写第二份。
- **`validateTask` 返回错误对象**，key 与表单字段同名，UI 直接绑定：

```js
{ valid: false, errors: { title: '请输入任务标题' } }
```

- **日期用本地时区拼接**，不要 `toISOString().slice(0, 10)`（UTC 会差一天）：

```js
`${year}-${month}-${day}`  // 来自 getFullYear / getMonth+1 / getDate
```

- **日期合法性要“回读比对”**：`new Date(2026, 1, 30)` 会进位到 3 月 2 日而不报错，所以要检查 year/month/day 是否与输入一致。

### 3.2 `board.js`：不可变更新

```js
const nextTasks = tasks.slice()
nextTasks[index] = nextTask
return nextTasks
```

- 不改原数组、不改原对象：Vue 的 `computed` / `watch` 靠**引用变化**判断更新，替换比原地修改更可靠。
- **结构共享**：只复制数组外壳，没改的任务对象保持同一个引用。
- `completedAt` 由状态派生（进入 done 写入、离开清空、停留保留），调用方传了也会被覆盖。
- `moveTask(tasks, id, toStatus, toIndex)` 的 `toIndex` 语义是“**移除该任务之后**，插入到目标列的第几位”。这个语义必须写进注释，否则同列移动会错一位。

### 3.3 `filter.js` / `stats.js`：派生数据不存

```js
const visibleTasks = computed(() => filterTasks(tasks.value, filter.value))
const stats = computed(() => summarize(visibleTasks.value))
```

- 筛选结果、计数、完成率都不写进状态，每次算。存一份就要同步一份，迟早不同步。
- 关键词在多个字段间是“或”，不同条件之间是“与”。
- 逾期排除已完成任务；`today` / `week` 只看日期，不看状态——这是业务语义，不是代码不一致。

### 3.4 `storage.js`：信任边界

`localStorage` 与网络响应一样属于**不可信输入**：

- 读取时逐层校验：外壳是对象 → `tasks` 是数组 → 每条任务字段合法
- 坏 JSON / 未知版本 → `corrupted`，回退空看板
- 部分任务非法 → `partial`，丢弃坏的、保留好的
- 写入失败 → 返回 `quota` / `unavailable`，由 UI 提示并降级内存存储

`getDefaultStorage()` 用“写一个探针再删掉”判断可用性，因为隐私模式下 `localStorage` 对象存在但 `setItem` 会抛错。

## 4. 状态层：`useBoard.js`

这是唯一依赖 Vue 的业务文件，做了四件事：

```js
const tasks = ref(initial.tasks)          // 状态
const visibleTasks = computed(...)        // 派生
watch(tasks, save)                        // 副作用
return { tasks: readonly(tasks), addTask, ... }  // 只读状态 + 命令
```

要点：

- **`readonly` 锁住状态**：组件拿不到可写引用，只能调命令。约定不如机制。
- **`watch` 默认异步批处理**：连续三次 `addTask` 只触发一次写盘。
- **不用 `deep: true`**：状态是整体替换的，浅监听足够。
- **`useBoard()` 不是单例**：只在 `App.vue` 调用一次，其他组件通过 props 拿数据。重复调用会得到两份互不相干的状态。
- **I/O 结果建模成 `ref`**：`loadStatus` / `saveStatus` 是数据，提示文案由 UI 决定。状态层不弹 Toast。

## 5. 组件层

### 5.1 展示组件：props 进、事件出

`TaskCard.vue` 不 import `useBoard`，只接收 `task`，发 `edit` / `remove` / `status`。

```js
defineEmits(['edit', 'remove', 'status'])
$emit('remove', task)   // 带上载荷，父级不用反查
```

**自定义事件不会冒泡**，所以 `BoardColumn` 必须显式转发：

```html
<TaskCard @edit="emit('edit', $event)" />
```

### 5.2 表单：草稿态与校验

`TaskFormDialog.vue` 用独立的 `reactive(form)` 承接输入，提交时才发事件：

- 取消 → 直接销毁，原数据没被动过
- 提交 → `validateTask` 统一校验 → 不合法则写 `errors` 并聚焦第一个错误控件
- `nextTick` 后再 `querySelector('[aria-invalid="true"]')`，因为 DOM 还没更新
- 浏览器原生校验被 `novalidate` 关闭，避免两套规则打架

编辑复用同一组件：传 `task` 即进入编辑模式。

### 5.3 拖拽：坐标换算

- `draggable="true"`，`dragstart` 记录 id；`dragover` 必须 `preventDefault()` 才会触发 `drop`
- 落点用**槽位 slot**（插到第几张之前），再换算成 `moveTask` 需要的下标：

```js
export function toMoveIndex(fromIndex, slot) {
  return fromIndex !== -1 && fromIndex < slot ? slot - 1 : slot
}
```

同列向下移动要减 1，这是唯一容易错的地方，所以单独抽成纯函数。

- 跨列共享状态用 `provide/inject`（`DRAG_KEY`），避免逐层传回调
- 筛选时禁用拖拽：可见列表与真实数组顺序不同，下标无法安全换算

### 5.4 键盘：焦点管理

- 卡片 `tabindex="0"` + `data-task-id`，进入 Tab 序列
- 只处理“焦点在卡片本身”的按键：`if (event.target !== event.currentTarget) return`
- 移动后卡片会重新挂载，焦点会丢；`nextTick` 后按 `data-task-id` 找回并 `focus()`
- 全局 `N` 快捷键要排除输入框 / 可编辑区域
- 监听器在 `onUnmounted` 移除

### 5.5 可访问性

- 对话框：`role="dialog"` / `role="alertdialog"` + `aria-modal` + `aria-labelledby`
- 错误提示：`aria-invalid` + `aria-describedby` 关联到错误文本
- Toast：容器常驻 + `aria-live="polite"`，动态内容才会被播报
- 删除确认默认聚焦“取消”，避免回车误删
- 视觉信息不只用颜色：完成态用“划线 + 变灰”，优先级用“文字 + 色块”

## 6. App 是“编排者”

`App.vue` 不写业务规则，只做四件事：

1. 持有 UI 状态（弹窗开关、待删任务、Toast）
2. 调 `useBoard` 的命令
3. 把组件事件接到命令上
4. 把机器状态翻译成人话（`quota` → “存储空间不足，本次修改未保存”）

组件多起来之后，`App` 会变长。本项目的处理顺序是：先抽 `useToast`，再抽 `useKeyboardMove`，最后把样式外置到 `app.css`。**每次都在超过 200 行之前拆，而不是之后。**

## 7. 为什么没有用那些库

| 需求 | 常规方案 | 本项目 | 原因 |
| --- | --- | --- | --- |
| 多页面 | vue-router | 单视图 + 条件渲染 | 只有一个页面 |
| 全局状态 | Pinia | `useBoard()` + props | 单一状态源足够 |
| UI 组件 | Element Plus 等 | 手写 CSS + 令牌 | 体积可控、无额外依赖 |
| 拖拽 | SortableJS | HTML5 DnD | 原生够用，且有键盘替代 |
| 测试 | Vitest + Testing Library | 人工验收 | 无测试依赖；逻辑已抽成纯函数，未来可低成本补测 |
| 日期 | dayjs | `Intl.DateTimeFormat` | 只做格式化，原生足够 |

这不是“原生更高级”，而是**约束下的取舍**。如果项目要增长（多视图、协作、复杂权限），这些决策都该重新评估。

## 8. 常见问题

**Q：为什么打开 `index.html` 是白屏？**
A：`.vue` 和裸模块导入需要构建工具处理，必须走 `npm run dev`，不能双击文件。

**Q：为什么 `App.vue` 里没有 `export default`？**
A：`<script setup>` 的导出由编译器生成，源码里写 `export` 会报错。

**Q：为什么改 `tasks` 没有触发视图更新？**
A：本项目要求整体替换（`tasks.value = next`）。如果原地 `push`，`watch(tasks)` 不会触发。用 `board.js` 里的命令，它们已经做了替换。

**Q：为什么拖拽时索引总差一位？**
A：`toMoveIndex` 的语义是“移除后的下标”。同列移动、原位置在落点之前时要减 1。

**Q：为什么筛选时不能拖拽？**
A：可见列表只是真实数组的子集，第 3 张卡片在第 2 个位置，下标无法一一对应。此时用“移动到”下拉或键盘。

**Q：怎么加一个新字段（比如“预估工时”）？**
A：按这个顺序改：`task.js`（默认值、校验、LIMITS）→ `TaskFormDialog.vue`（输入项）→ `TaskCard.vue`（展示）→ `storage.js`（如果需要兼容旧数据，升 `SCHEMA_VERSION` 并在 `migrate` 里补默认值）。

**Q：怎么改主题色？**
A：只改 `src/styles/tokens.css` 里的 `--primary` 等令牌，不要改组件。

## 9. 动手练习

1. **加字段**：给任务加 `estimate`（预估小时），要求 0–100 的整数，卡片上显示。
2. **加筛选**：增加“仅看我的任务”（`assignee` 非空）。
3. **加排序**：按截止日期或优先级排序（在 `filter.js` 里加纯函数，`useBoard` 里加一个 `computed`）。
4. **加撤销删除**：删除后 5 秒内 Toast 提供“撤销”，需要保存被删任务与原位置。
5. **抽组件**：把 `TaskCard` 的“徽章 + 标签 + 日期”抽成 `TaskMeta.vue`，体会“按职责拆分”。
6. **改存储**：把 `localStorage` 换成 `IndexedDB` 的适配器，只改 `storage.js`，其余不动——验证分层是否真的解耦。
7. **加测试**：如果以后允许装依赖，给 `src/domain/**` 补 Vitest 单元测试；它们没有任何 Vue 依赖，迁移成本最低。

## 10. 调试技巧

- **Vue Devtools → Timeline**：看一次拖拽触发了哪些响应式更新
- **`watch(tasks, console.log)`** 临时打开：确认写盘时机
- **Application → Local Storage**：确认 `schemaVersion` 与数据形状
- **手动制造损坏数据**：控制台执行 `localStorage.setItem('vue-kanban:board', '{oops')` 后刷新，验证兜底
- **无痕窗口**：验证存储不可用时的降级提示

## 11. 术语表

| 术语 | 含义 |
| --- | --- |
| 领域层 | 只含业务规则的纯 JS 模块，不依赖框架 |
| 组合式函数 | 以 `useXxx()` 返回状态与命令的函数 |
| 槽位（slot，拖拽语境） | 插入到“第几张卡片之前”的位置，与数组下标不同 |
| 派生数据 | 由状态计算得出、不单独存储的数据（`computed`） |
| 不可变更新 | 返回新对象/新数组，不修改原值 |
| 信任边界 | 外部输入（localStorage、URL、表单）进入系统前必须校验的位置 |
