## 1. 引言

### 1.1 目的

本文档定义"任务看板"单页应用（SPA）的功能需求、非功能需求、数据模型、交互规格、架构与质量保证方式，作为后续编码与验收的唯一依据。所有实现工作必须以本文档为准，需求变更需先更新本文档。

### 1.2 背景

仓库当前为 Vue 3 + Vite 官方起步模板。目标是把它改造成一个可运行、可交互、带中文教学文档的任务看板，同时作为 Vue 3 组合式 API 的学习载体。

### 1.3 读者对象

开发者（学习者本人）、评审者、后续维护者。

### 1.4 术语

| 术语 | 含义 |
| --- | --- |
| 看板 / Board | 由三列组成的任务视图 |
| 列 / Column | 任务状态分组：待办、进行中、已完成 |
| 卡片 / Card | 一个任务的可视化表示 |
| 领域层 / domain | 纯 JavaScript 业务逻辑，不依赖 Vue 与 DOM |
| 组合式函数 / composable | 以 `useXxx()` 形式复用状态逻辑的函数 |
| DnD | HTML5 Drag and Drop API |

### 1.5 参考

- Vue 3 官方文档（组合式 API、组件、插槽）
- Vite 8 配置文档
- WCAG 2.1 AA（可访问性）

## 2. 总体描述

### 2.1 产品定位

单用户、纯前端、离线可用的个人任务看板。无后端、无账号、无网络请求，数据保存在浏览器 `localStorage`。

### 2.2 目标用户与用户故事

| 编号 | 用户故事 |
| --- | --- |
| US-01 | 作为使用者，我想快速新建任务并归类到三列之一，以便记录今天要做的事 |
| US-02 | 作为使用者，我想把卡片拖到"进行中"或"已完成"，以便直观反映进度 |
| US-03 | 作为使用者，我想按关键词和优先级筛选，以便在任务多时快速定位 |
| US-04 | 作为使用者，我想刷新页面后任务还在，以便不用担心误关页面 |
| US-05 | 作为键盘使用者，我不使用鼠标也能完成移动和编辑，以便无障碍操作 |

### 2.3 运行环境

- 现代浏览器（Chrome / Edge / Firefox / Safari 最近两个大版本），桌面为主，窄屏可读。
- Node.js ≥ 22.18（与 `package.json` 的 `engines` 一致），用于开发与构建。
- 不依赖网络；不依赖后端服务。

### 2.4 设计与实现约束（强制）

**依赖白名单**：仅允许使用下列已安装能力，禁止任何 `npm install` / `pnpm add`。

| 能力 | 版本 | 来源 | 用途 | 新增 |
| --- | --- | --- | --- | --- |
| vue | 3.5.44 | 直接依赖 | 运行时、响应式、组件 | 否 |
| vite | 8.3.5 | 直接依赖 | 开发服务器、生产构建 | 否 |
| @vitejs/plugin-vue | 6.0.10 | 直接依赖 | `.vue` 编译 | 否 |
| vite-plugin-vue-devtools | 8.2.1 | 直接依赖 | 开发调试 | 否 |

**明确禁止**：vue-router、pinia、vitest、@vue/test-utils、jsdom、happy-dom、playwright、cypress、任何 UI 组件库、任何拖拽/日期/工具库、CSS 框架。

**由此产生的设计约束**：

1. 无路由 → 单视图；弹窗、确认框用条件渲染实现"页面级"切换。
2. 无 Pinia → 单一 `useBoard()` 组合式函数作为唯一状态源，子组件通过 props/emit 通信。
3. 无测试框架（不引入自动化测试）→ 业务规则集中到 `domain/` 纯函数，逻辑与视图分离，便于阅读、复用和日后按需补充验证；交付质量由人工验收清单与构建检查保证。
4. 无 UI 组件库 → 手写 CSS + 设计令牌 + 内联 SVG 图标。
5. 无 lint/格式化工具 → 在文档中约定代码风格（2 空格缩进、单引号、无分号、组件文件 PascalCase），提交前人工检查。

### 2.5 假设

- 用户数据量级 ≤ 2000 条任务。
- 同一浏览器单标签页使用，不考虑多标签页并发写入冲突。
- `localStorage` 可用（隐私模式可能不可用，需降级为内存存储并提示）。

## 3. 功能需求

优先级采用 MoSCoW：Must / Should / Could / Won't。

| 编号 | 功能 | 优先级 | 验收标准（摘要） |
| --- | --- | --- | --- |
| FR-01 | 三列看板展示 | Must | 页面显示"待办 / 进行中 / 已完成"三列，各列显示任务数与卡片列表，顺序与数据数组一致 |
| FR-02 | 新建任务 | Must | 点击"新建任务"打开表单；标题必填≤80 字；提交后卡片出现在"待办"列首位；非法输入有字段级错误提示且不提交 |
| FR-03 | 编辑任务 | Must | 点击卡片编辑按钮打开表单并回填；保存后列表即时更新，`updatedAt` 变化 |
| FR-04 | 删除任务 | Must | 点击删除弹出确认框；确认后卡片消失；取消不改变数据 |
| FR-05 | 拖拽跨列移动 | Must | 拖动卡片到另一列，松开后 `status` 改变并落在释放位置；拖动中有落点高亮 |
| FR-06 | 列内拖拽排序 | Must | 同一列内拖动可改变顺序，顺序持久化 |
| FR-07 | 非拖拽移动 | Must | 卡片菜单/键盘可把任务移动到相邻列，供触屏与键盘用户使用 |
| FR-08 | 关键词搜索 | Must | 输入即时过滤标题/描述/标签，匹配不区分大小写；无结果显示空状态 |
| FR-09 | 条件筛选 | Should | 可按优先级、截止状态（逾期/今天/本周）筛选；多条件为"与"关系 |
| FR-10 | 统计信息 | Should | 各列数量、总完成率、逾期数量实时更新 |
| FR-11 | 本地持久化 | Must | 刷新页面后数据与顺序完整恢复；损坏数据不导致白屏，回退为空看板并提示 |
| FR-12 | 空状态引导 | Should | 无任务/无筛选结果时显示对应文案与主行动按钮 |
| FR-13 | 操作反馈 | Should | 新建、编辑、删除、移动后出现轻量 Toast，3 秒自动消失 |
| FR-14 | 响应式布局 | Should | 360px 宽度可用；≥1024px 三列并排；窄屏纵向排列 |
| FR-15 | 暗色模式 | Could | 跟随系统 `prefers-color-scheme`，无需手动开关 |
| FR-16 | 无障碍 | Must | 键盘可完成全部操作；焦点可见；Toast 通过 `aria-live` 播报；对比度达 AA |
| FR-17 | 删除可撤销 | Could | 删除后 5 秒内 Toast 提供"撤销"，恢复任务与原位置（默认不实现，视评审） |

### 3.2 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-01 | 标题去除首尾空格后长度 1–80；描述 ≤500；标签最多 5 个、每个 1–12 字符；负责人 ≤20 |
| BR-02 | 新建任务默认 `status='todo'`、`priority='medium'`、`tags=[]`、`dueDate=null` |
| BR-03 | 任务进入 `done` 时写入 `completedAt`；离开 `done` 时置空 |
| BR-04 | 列内顺序由任务数组顺序决定，移动即"删除后插入到目标索引" |
| BR-05 | 逾期定义：`dueDate < 今天` 且 `status !== 'done'` |
| BR-06 | 日期以 `YYYY-MM-DD` 存储，展示用 `Intl.DateTimeFormat('zh-CN')` |
| BR-07 | 删除立即生效，无回收站（FR-17 为可选项） |
| BR-08 | 筛选与搜索只影响展示，不修改数据 |

### 3.3 关键用例

**UC-01 新建任务（异常路径）**

1. 用户点击"新建任务"，表单以对话框出现，焦点落在标题输入框。
2. 用户不填标题直接提交。
3. 系统阻止提交，标题下方显示"请输入任务标题"，焦点回到标题框。
4. 用户填写合法标题后提交，对话框关闭，卡片出现在待办列顶部，出现 Toast。

**UC-02 拖拽并刷新**

1. 用户按住"待办"列卡片拖到"进行中"列中间位置。
2. 目标位置显示插入指示线，松开后卡片移入该位置。
3. 刷新页面，卡片仍在"进行中"列的原位置。

**UC-03 搜索与筛选叠加**

1. 用户在搜索框输入"文档"。
2. 系统仅显示标题/描述/标签包含"文档"的卡片，三列计数同步变为过滤后数量。
3. 用户再勾选"高优先级"，结果进一步收窄；点击"清空筛选"恢复全部。

**UC-04 数据损坏**

1. `localStorage` 中数据不是合法 JSON。
2. 系统捕获异常，使用空看板启动，控制台告警并显示一次 Toast 提示"本地数据读取失败，已重置"。

## 4. 非功能需求

| 编号 | 类别 | 指标 |
| --- | --- | --- |
| NFR-01 | 性能 | 2000 条任务下，筛选/统计纯函数单次执行 < 50ms；拖拽跟手无明显掉帧 |
| NFR-02 | 可用性 | 核心操作（新建、移动、完成）≤2 次交互；所有异步/持久化操作有反馈 |
| NFR-03 | 可访问性 | 键盘可完成建、改、删、移动；焦点可见；语义化标签；`aria-live="polite"` 播报 |
| NFR-04 | 兼容性 | Chrome/Edge/Firefox/Safari 最近两个大版本；360px–1440px 布局不破 |
| NFR-05 | 可维护性 | 单文件 ≤200 行；`src/domain/**` 不得 import `vue`；纯函数不读写全局状态；依赖方向单向向下 |
| NFR-06 | 安全 | 不使用 `v-html`；所有用户输入以文本插值渲染；本地数据视为不可信输入并校验 |
| NFR-07 | 依赖 | `package.json` 的 dependencies/devDependencies 不新增；生产构建 gzip 后 < 200KB |
| NFR-08 | 一致性 | 界面文案中文，代码标识符英文；术语与本文档一致 |

## 5. 数据需求

### 5.1 Task 模型

| 字段 | 类型 | 必填 | 约束 |
| --- | --- | --- | --- |
| id | string | 是 | `crypto.randomUUID()`，降级为时间戳+随机数 |
| title | string | 是 | 1–80 字符（trim 后） |
| description | string | 否 | 0–500 字符，默认 `''` |
| status | `'todo' \| 'doing' \| 'done'` | 是 | 默认 `todo` |
| priority | `'low' \| 'medium' \| 'high'` | 是 | 默认 `medium` |
| tags | string[] | 否 | 0–5 个，每个 1–12 字符 |
| assignee | string | 否 | 0–20 字符 |
| dueDate | string \| null | 否 | `YYYY-MM-DD` |
| createdAt | string | 是 | ISO 8601 |
| updatedAt | string | 是 | ISO 8601 |
| completedAt | string \| null | 否 | 进入 done 时写入 |

顺序不在字段中保存，由 `tasks` 数组下标决定。

### 5.2 状态机

```
        ┌──────────┐  拖拽/移动   ┌──────────┐  拖拽/移动   ┌──────────┐
        │   todo   │ ───────────► │  doing   │ ───────────► │   done   │
        └──────────┘ ◄─────────── └──────────┘ ◄─────────── └──────────┘
              ▲                          │                         │
              └──────────────────────────┴─────────────────────────┘
                        任意状态之间可直接互移（看板语义）
```

进入 `done`：写 `completedAt`；离开 `done`：清空。

### 5.3 持久化格式与迁移

```json
{
  "schemaVersion": 1,
  "tasks": [ { "...": "Task" } ]
}
```

- 存储键：`vue-kanban:board`
- 读取流程：读取 → `JSON.parse` → 校验 `schemaVersion` 与每项字段 → 丢弃非法项 → 返回状态；任一步失败则返回空状态并标记 `corrupted=true`
- 迁移策略：`migrate(raw)` 按 `schemaVersion` 逐级升级；当前仅 v1，预留 v2（如增加 `order` 字段）
- 写入失败（配额/隐私模式）：降级为内存存储，Toast 提示"本次修改不会被保存"

## 6. 界面与交互规格

### 6.1 页面结构（桌面）

```
┌──────────────────────────────────────────────────────────────┐
│ 看板标题            完成率 40% · 逾期 2      [新建任务]      │
│ [搜索…]  [优先级 ▾]  [截止 ▾]  [清空筛选]                    │
├──────────────────┬──────────────────┬────────────────────────┤
│ 待办 (3)  [+]    │ 进行中 (2)  [+]  │ 已完成 (5)  [+]        │
│ ┌──────────────┐ │ ┌──────────────┐ │ ┌──────────────┐       │
│ │ 标题         │ │ │ 标题         │ │ │ 标题         │       │
│ │ 描述摘要     │ │ │ 标签 截止日  │ │ │ 完成时间     │       │
│ │ 优先级 标签  │ │ │ ⋯ 菜单       │ │ │              │       │
│ └──────────────┘ │ └──────────────┘ │ └──────────────┘       │
└──────────────────┴──────────────────┴────────────────────────┘
```

### 6.2 交互规则

| 操作 | 鼠标 | 键盘 |
| --- | --- | --- |
| 新建 | 点击"新建任务" / 列头"+" | `N`（页面无输入焦点时）→ 打开表单 |
| 打开编辑 | 点击卡片正文 | 卡片聚焦后 `Enter` |
| 移动 | 拖拽 | 卡片聚焦后 `Ctrl/⌘ + ←/→` 移到相邻列 |
| 列内排序 | 拖拽 | 卡片聚焦后 `Ctrl/⌘ + ↑/↓` |
| 删除 | 卡片菜单 → 删除 → 确认 | 卡片聚焦后 `Delete` → 确认 |
| 关闭弹窗 | 点击遮罩 / 取消 | `Esc` |

拖拽细节：`draggable="true"`；`dragstart` 记录 id；目标卡片上/下半区分别表示插入前/后，显示 2px 指示线；`drop` 时按"目标列 + 索引"调用领域函数。

### 6.3 视觉规范

- 设计令牌（CSS 变量）：`--bg`、`--surface`、`--text`、`--muted`、`--border`、`--primary`、`--danger`、`--warning`、`--success`、`--radius`、`--shadow`，定义在 `src/styles/tokens.css`。
- 断点：`< 768px` 单列纵向；`768–1023px` 两列；`≥ 1024px` 三列并排。
- 优先级色：高=红、中=琥珀、低=灰蓝，均以文字+色块双重编码（不只靠颜色）。
- 焦点样式：`outline: 2px solid var(--primary); outline-offset: 2px`，不得 `outline: none`。

## 7. 架构设计

### 7.1 分层与依赖方向

```
components/ ──依赖──► composables/ ──依赖──► domain/
     │                    │
     └──── 只读 props ─────┘
domain/ 不依赖 vue、不依赖 DOM、不依赖 components（依赖单向向下）
```

分层的目的：业务规则与渲染解耦，改样式不影响规则、改规则不碰组件；纯函数可被任意调用方复用（包括未来可能出现的测试）。

### 7.2 目录结构（目标）

```
src/
├── main.js
├── App.vue
├── styles/
│   ├── tokens.css          # 设计令牌
│   └── global.css          # 基础重置与排版
├── domain/
│   ├── task.js             # 模型、常量、校验、id、日期
│   ├── board.js            # 增删改、移动、重排
│   ├── filter.js           # 搜索与筛选
│   ├── stats.js            # 统计
│   └── storage.js          # 序列化、迁移、localStorage 适配
├── composables/
│   ├── useBoard.js         # 唯一状态源
│   └── useDragDrop.js      # 拖拽状态
├── components/
│   ├── AppHeader.vue
│   ├── BoardToolbar.vue
│   ├── BoardColumn.vue
│   ├── TaskCard.vue
│   ├── TaskFormDialog.vue
│   ├── ConfirmDialog.vue
│   ├── ToastHost.vue
│   └── EmptyState.vue
docs/
├── 需求规格说明书.md
├── 教学文档.md
└── 验收清单.md
```

### 7.3 数据流

单向：`useBoard` 持有 `tasks` 与 `filter` → 派生出 `visibleTasks`、`columns`、`stats`（computed）→ 组件只读渲染 → 用户操作调用 `addTask/updateTask/removeTask/moveTask/setFilter` → 内部调用 `domain` 纯函数生成新数组 → 赋值触发视图更新 → `watch` 持久化到 `localStorage`。

禁止子组件直接改 props；禁止在组件里直接操作 `localStorage`。

### 7.4 关键技术决策（ADR）

| 编号 | 决策 | 理由 | 代价 |
| --- | --- | --- | --- |
| ADR-01 | 不引入 vue-router | 只有单视图，弹窗用 `ref` 控制 | 无法深链到某个任务 |
| ADR-02 | 不引入 Pinia | 单页面单状态源，composable 足够 | 跨页面复用需重构 |
| ADR-03 | 不引入拖拽库 | 约束禁止；HTML5 DnD 够用 | 移动端 DnD 不支持，用键盘/菜单兜底 |
| ADR-04 | 不引入 UI/CSS 框架 | 约束禁止；手写 CSS 可控且体积小 | 样式代码量增加 |
| ADR-05 | 不做自动化测试 | 无测试库且不新增依赖；交付质量由人工验收 + 构建检查保证 | 没有回归保护，重构需人工复核 |
| ADR-06 | domain 与 Vue 解耦 | 规则集中、可读性高、日后可低成本补测 | 需要在 composable 里做一层响应式包装 |

## 8. 质量保证与验收

### 8.1 质量手段

| 手段 | 时机 | 说明 |
| --- | --- | --- |
| 人工验收清单 | 每步完成后 | 按 `docs/验收清单.md` 逐项操作，记录通过/失败 |
| 可运行性检查 | 每步完成后 | `npm run dev` 启动无报错，浏览器控制台无 error/warning |
| 构建检查 | 引入初版功能后、收尾时 | `npm run build` 成功 |
| 代码走查 | 每步提交前 | 对照 NFR-05：文件长度、依赖方向、纯函数约束 |
| 手工回归 | 改动 domain 层后 | 至少复核：新建、拖拽、刷新恢复三条主路径 |

## 11. 风险与应对

| 风险 | 可能性 | 影响 | 应对 |
| --- | --- | --- | --- |
| 无自动化回归，改动可能破坏旧功能 | 高 | 中 | 小步提交；每步按验收清单复核三条主路径（新建、拖拽、刷新恢复）；规则集中在 `domain/`，日后可低成本补测 |
| 无 DOM 测试，拖拽缺陷只能在人工验收时暴露 | 中 | 中 | 目标位置计算抽成纯函数；拖拽列入验收清单第 2 项，每次改动必验 |
| 手写 CSS 在窄屏错位 | 中 | 低 | 三档断点手工验收；优先用 flex/grid |
| localStorage 损坏或超限 | 低 | 高 | 读取全程 try/catch + 字段校验 + 降级内存存储 |
| 步骤粒度过大导致单次改动难评审 | 中 | 中 | 每步一个 commit；超过 200 行时强制拆分 |
| 需求蔓延（撤销、多看板、日历视图） | 高 | 中 | 本文档 2.4 节明确禁止项；新增需求先改 SRS |
